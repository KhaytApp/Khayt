- **Mac: four fixes from the beta.43 release review.** A paired phone's request that names the same field twice (`{"status":"pending","status":null}`) is now refused: the Mac's role check and the change it made read such a body differently, so an operator's phone could price a job or move a quote on, which only a manager may do. A phone's pause, stop and "bed is clear" now obey the shop's own per-printer limits (Roles ▸ Printers), as the Mac's own buttons do. "An update is ready" is shown even when another sheet was open the moment an update was found (it could stay hidden until a restart, with the update held); it now waits for that sheet to close, and **Check for Updates…** always brings it back. Failed accounting pushes wait while the shop makes no internet calls, as webhook retries do. And "bed is clear" refuses an API token, as the other phone-only routes do.
